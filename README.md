# Claude Usage Dock

A PowerToys Command Palette **Dock band** that shows your Claude session (5 h) and weekly (7 d) usage.

<p align="center">
  <img src="docs/dock-band.png" alt="Dock band: 5h ring at 49%, 7d ring at 14%, reset timer 15:40" width="298">
</p>

- **Ring buttons** (one per quota): the ring fills to the % used and is colored by level: blue < 60 %, amber 60–84 %, red ≥ 85 %. Dock text can't be colored, so the ring carries it. Click to open the detail page (all limits, reset times); opening it refreshes if the data is older than 30 s.
- **Timer button**: the 5-hour reset time. Click to **refresh now**. When a limit is maxed out, it switches to a countdown ("in 1 h 12 min").
- **No data** (signed out, loading, offline): the rings are replaced by a single status button: gauge icon + "Sign in" / "Claude" / "Offline" (grey with "!" = sign in needed).
- **Right-click any button**: Refresh now / Open usage page / Open details / **Sign in with Claude Code**.
- **Sign in with Claude Code** opens a terminal running `claude` (Windows Terminal if installed, otherwise PowerShell) so you can log in or let Claude Code renew its login. The band picks up the new login within 60 s. On the detail page, the "Sign in" row does the same when clicked. The extension only opens the terminal; it never handles the login itself.
- Palette commands (Win+Alt+Space): **Claude usage**, **Refresh Claude usage**.

## Requirements

- Windows 11, **PowerToys 0.100 or newer** with Command Palette enabled and the Dock turned on (Command Palette → Settings → Dock → Enable Dock).
- **Developer Mode** on (Settings → System → For developers), so you can install your own unsigned package.
- **Claude Code installed and logged in** (the extension reuses its sign-in; see Security).
- One of:
  - **No Visual Studio:** the **.NET 10 SDK** (`winget install Microsoft.DotNet.SDK.10`). VS Code is optional, just for editing.
  - **Visual Studio 2026** with the workloads in `.vsconfig`.

## Build and install, no Visual Studio (VS Code or plain PowerShell)

1. Extract to a short, non-OneDrive path, e.g. `C:\Dev\ClaudeUsageDock`.
2. In that folder, run:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\deploy.ps1
   ```
   In VS Code: open the folder and press **Ctrl+Shift+B** (runs the same script).
   The script builds, then registers the package with Windows (`Add-AppxPackage -Register`), which is what Visual Studio's Deploy does. The extension runs from the `bin` folder, so keep it.
3. Open Command Palette (Win+Alt+Space) and run **Reload**.
4. Add the band: right-click the Dock → **Edit Dock** → **+** → **Claude usage**, then save.

Update after a code change: run the script again, then **Reload**. Remove it: `.\deploy.ps1 -Uninstall`.

## Build and install with Visual Studio 2026

1. Open `ClaudeUsageDock.sln`, set **Debug | x64** (or ARM64).
2. **Build → Deploy Solution**.
3. Command Palette → **Reload**, then Edit Dock → **+** → **Claude usage**.

## How it refreshes

| Situation | Poll interval |
|---|---|
| Under 60 % | 5 min |
| 60–84 % | 2 min |
| 85 %+, or the 5 h / 7 d window resets within 10 min | 1 min |
| No keyboard/mouse input for 15 min (or screen locked) | paused |
| Click timer / Refresh now | immediately (10 s debounce) |
| Network/server error | backoff 1 → 2 → 4 → 8 → 15 min, last values kept as "Stale" |
| HTTP 429 | waits for `Retry-After` (min 60 s) |
| Token rejected (401) | stops calling the server until Claude Code writes a new token |

The reset countdown re-renders locally every 30 s with no network call. Every number lives in `ClaudeUsageDock/Core/Config.cs`.

## Security

- Reads the access token from `%USERPROFILE%\.claude\.credentials.json` (or `%CLAUDE_CONFIG_DIR%\.credentials.json`), **read-only**, fresh on every poll.
- Never copies, caches, logs, or refreshes the token. The refresh token is never read.
- Sends it only to `https://api.anthropic.com/api/oauth/usage` over HTTPS.
- No browser cookies, no Claude desktop app session, no password prompts.
- On a work laptop, check your IT policy first: some orgs treat one app reading another app's OAuth token as a policy issue even when both are yours.

## Known limits

- **Unofficial endpoint.** It's the one Claude Code itself uses; Anthropic can change it without notice. All endpoint knowledge is isolated in `Core/UsageClient.cs` + `Core/UsageParser.cs`.
- **Token expiry.** Claude Code renews its token when it runs. If you haven't used Claude Code for a while, the band shows **Sign in** until you open Claude Code again. This extension deliberately doesn't renew tokens itself.
- Logins stored only in Windows Credential Manager (some IDE-extension-only setups) aren't read in v0.1. A CLI login always writes the credentials file.
- If the server answers **403**, it may be rejecting the custom User-Agent: change `Config.UserAgent` and redeploy.

## Customizing

- **Icons**: all artwork is generated by `tools/make_icons.py` (`pip install pillow`, then `python tools/make_icons.py`). Edit colors or sizes there and rerun. Rings live in `Assets/Rings/ring-<ok|warn|crit>-<000..100>.png`; the status gauge is `Assets/gauge-*.png` (64×64 transparent PNGs, `gauge-for-light-theme.png` on a light Dock, `gauge-for-dark-theme.png` on a dark one).
- **Diagnostics**: `.\diag.ps1` checks the credentials file (structure only, never the token) and makes one test call to the usage endpoint.
- **Thresholds / intervals**: `Core/Config.cs`.
- **Text**: `Core/Format.cs` (24 h clock, dd/MM dates).

## Project layout

```
ClaudeUsageDock/
  Program.cs, ClaudeUsageDockExtension.cs     COM server entry (from the official template)
  ClaudeUsageDockCommandsProvider.cs          palette commands + GetDockBands()
  Core/        portable logic, no Windows deps (config, parser, credentials, HTTP, policy, poller, formatting)
  Dock/        the two dock buttons + 30 s re-render controller, icons
  Pages/       detail page
  Commands/    refresh command, ids
  Platform/    idle detection (GetLastInputInfo)
  Assets/      icons and package logos
```

Built on the official PowerToys Command Palette extension template (MIT) and SDK 0.11.260520004 (PowerToys 0.100).
